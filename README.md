# LEMONZ Mini App - голосование и аукционы

Обновление исходного Telegram Mini App. Каталог, корзина, профиль и админка товаров сохранены. **Главная страница перестроена по присланному референсу:** светлая сиреневая шапка, широкая фиолетовая промопанель, две компактные карточки **ГОЛОСОВАНИЕ** и **АУКЦИОН**, горизонтальные категории, листаемые пальцем ряды «Популярное» и «Новинки», нижняя навигация. Промоблоки используют пользовательский макет `public/home-reference.png`, а подборки фигурок показывают только реальные товары из каталога с включёнными администратором отметками. Фотографии, названия и цены берутся из каталога, без демонстрационных персонажей и кнопок «Смотреть все».

## Возможности

**Каталог:** отдельная страница в стиле главной, по три карточки в ряд на смартфоне, сортировка, поиск и горизонтальный выбор вселенной. Для каждой вселенной доступны собственные подкатегории **«Фигурки», «Брелки», «Лампы», «Декор»**. В админ-панели подкатегория задаётся при создании и редактировании товара; ранее добавленные товары без этого поля автоматически относятся к «Фигуркам». При выборе пустой подкатегории показывается сообщение об отсутствии товаров. Как и раньше, товарный каталог хранится локально в браузере: для синхронизации админских изменений между всеми пользователями потребуется отдельный общий серверный каталог.

**Оформление и темы:** на главной странице рядом со значком поиска находится переключатель светлой и тёмной темы (луна/солнце). Выбранная тема запоминается на устройстве и применяется к каталогу, экрану фигурки, голосованию, аукциону, корзине, профилю и админке. Светлая версия использует сиреневые акценты и чёрные кнопки, тёмная - глубокий сливовый фон с контрастным светлым текстом. Карточка товара открывается во весь экран на смартфоне, показывает крупное фото, текущую стоимость, избранное, персонализацию и закреплённую кнопку добавления в корзину.

**Промокоды в корзине:** блок для ввода появляется только при наличии товаров. После нажатия «Применить» сервер проверяет код; ниже сразу показываются исходная сумма, скидка и новый итог. При изменении количества фигурок процентная скидка пересчитывается сразу. Можно убрать код, затем ввести другой. Общие процентные промокоды создаются, изменяются и отключаются во вкладке **«Админ» → «Промокоды»**. Старые коды из серверной переменной `LEMONZ_PROMO_CODES` (например, `LEMONZ10:10,FRIENDS15:15`) тоже отображаются и могут быть переопределены: запись в БД имеет приоритет, в том числе при отключении старого кода. Персональные одноразовые коды победителей голосования показываются в той же вкладке отдельно: они фиксированы на 50% на одну фигурку выигравшего персонажа и доступны только автору под его Telegram-аккаунтом. Перед отправкой заказа сервер повторно проверяет код и пересчитывает стоимость; администратор получает код и сумму скидки в заказе. Одноразовую скидку администратор помечает использованной **после подтверждения оплаты**, поскольку оформление заказа само по себе не означает оплату. В обычном `npm run dev` без API можно создавать и редактировать пробные коды, но они работают лишь на текущем устройстве и не подходят для реальной покупки.

**Баннер главной:** слева и справа появились кнопки переключения слайдов. Автоматическое перелистывание остаётся, после ручного нажатия отсчёт до следующего слайда начинается заново.

**Обновлённая админ-панель:** четыре вкладки: «Фигурки», «Голосование», «Аукцион», «Промокоды». Во вкладке голосования можно редактировать и удалять персонажей **уже идущего сезона**, сохранять ранее поданные голоса при изменении, удалять голоса и комментарии вместе с персонажем, добавлять новые варианты LEMONZ (до трёх), редактировать предложения сообщества и выбирать срок голосования (1, 3, 7, 14, 30 дней или собственные даты начала и окончания). Также доступны завершение сезона, удаление комментариев, блокировка нарушителей и отметка скидки использованной. Во вкладке аукциона можно создать и изменить лот с фотографиями, размером и настройками ставок, посмотреть историю ставок, завершить или отменить торги, подтвердить оплату и разблокировать участника. Во вкладке промокодов видны активные, отключённые и персональные коды; общий код можно создать, переименовать, изменить процент (1–90%), отключить или вернуть в работу. Отключение вместо физического стирания позволяет безопасно восстановить код. Реальные изменения требуют Telegram-авторизации администратора и настроенного API. В демо-режиме правки персонажей, сроков и общих промокодов доступны только локально на устройстве, остальные серверные действия отключены.

**Голосование:** 2 категории с одним переносимым/отменяемым голосом на Telegram ID в каждой; предложение персонажей с фото; проверка дублей на сервере (транслитерация, альтернативные имена, опечатки); комментарии с фото/GIF; сезоны по умолчанию 14 дней, но администратор может изменить период от 15 минут до 90 дней, в том числе назначить будущий старт; 2 победителя, архив, исключение победителей из следующих сезонов. Автор победившего предложения получает персональный одноразовый код на скидку 50%. После удаления участника голоса за него освобождаются, при изменении участника голоса сохраняются.

**Экран голосования по референсу:** тёмный баннер с фигурками LEMONZ, заголовок с таймером и линией прогресса, сразу два списка подряд - «Выбор LEMONZ» и «Выбор сообщества» без вкладок. Компактные карточки показывают фото, автора, количество голосов, рейтинг и кнопку комментариев; выбранный голос отмечен сиреневой галочкой. Внизу есть крупная кнопка «Предложить дизайн», ссылка на прошлые сезоны и раскрывающиеся правила. Для демонстрации без сервера предусмотрены 6 тестовых карточек, реальное голосование остаётся серверным.

**Аукцион:** активные и завершённые лоты; фотографии, таймер и история ставок; шаг от 500 ₽ (настраивается); бесплатное участие без предоплаты; согласие перед первой ставкой; подтверждение суммы; невозможность отменить ставку; транзакционная защита конфликтующих ставок. Ставка в последние 2 минуты продлевает таймер на 2 минуты. После победы даётся 24 часа на оплату, при неоплате - бан на 30 дней. Право выкупа переходит следующему участнику по его ставке; тот вправе отказаться без штрафа. Админ создаёт/редактирует лоты, подтверждает оплату, отменяет/завершает торги, снимает блокировки.

**Новый экран лота:** просмотр аукциона переделан по референсу: собственная верхняя панель, сохранение лота в закладки на устройстве, крупная галерея с листанием и счётчиком фотографий, метка 1/1, название и автор LEMONZ, общий сиреневый блок текущей ставки и таймера, индикатор активности, следующая ставка, крупная чёрная кнопка, компактная история ставок и заметка о доставке. Ввод суммы и подтверждение условий открываются в отдельной панели. Для первого демонстрационного лота используется изображение из присланного референса `public/auction-detail-reference.png`; тестовые ники, ставки и суммы явно обозначены как демонстрационные. После подключения сервера отображаются реальные фото, ставки и время, предоставляемые API.

**Главная аукциона:** список лотов также оформлен в едином стиле с референсом: собственная верхняя панель, большой избранный лот с фотографией, меткой эксклюзивности, ставкой, таймером и кнопкой перехода; ниже компактные карточки других фигурок. Доступны вкладки «Активные», «Завершённые» и «Сохранённые». Закладки синхронизированы между списком и экраном лота на том же устройстве. Демонстрационные Clove, Chamber и Jinx нужны только для просмотра дизайна: при подключённом сервере список и ставки заменяются настоящими.

**Важно:** если сервер голосования не настроен, кнопки голосования позволяют попробовать выбор, перенос и отмену голоса, а админ-панель - изменить/удалить тестовых персонажей и настроить период. Все **пробные изменения хранятся только в браузере пользователя** и не учитываются в общем рейтинге, выдаче скидок или результатах сезона. Доступна кнопка сброса пробных изменений. Реальные общие голоса и правки хранятся исключительно на сервере и требуют Telegram-авторизации. Серверные комментарии, предложения, ставки и управление настоящими блокировками недоступны без настройки.

## Подключение к Telegram и Supabase

1. Установите Node.js версии 20.19+ или 22.12+, затем `npm install`.
2. `npm run dev` запускает только фронтенд с демо-данными. Для тестирования API локально используйте `vercel dev`, для публикации - Vercel с HTTPS-доменом.
3. Создайте проект в Supabase. В SQL Editor выполните [`supabase/schema.sql`](supabase/schema.sql). Появится первый сезон и необходимые таблицы/транзакции. Если БД **уже была создана** в предыдущей версии, отдельно выполните миграцию [`supabase/migrations/20261024_promo_management.sql`](supabase/migrations/20261024_promo_management.sql) перед публикацией обновлённого API. Без неё новые общие промокоды и их список не заработают.
4. В Supabase Storage создайте **публичный** bucket `lemonz-media` с максимальным файлом 4 МБ и типами PNG/JPEG/WEBP/GIF. Лимит загрузки через Mini App - 3 МБ с учётом ограничений серверных запросов.
5. Создайте бота через BotFather, привяжите HTTPS-адрес Mini App. Пользователи должны сначала открыть бот (Start), иначе личные уведомления не доставятся.
6. Установите переменные окружения на сервере по `.env.example`:
   - `TELEGRAM_BOT_TOKEN` - секрет бота;
   - `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` - адрес и **секрет сервера**, никогда не добавлять в `VITE_*`;
   - `ADMIN_TELEGRAM_IDS` и `VITE_ADMIN_TELEGRAM_IDS` - одинаковые Telegram ID администратора, через запятую;
   - `CRON_SECRET` - длинный случайный секрет для планировщика;
   - `PAYMENT_INSTRUCTIONS` - инструкции победителю по оплате после аукциона;
   - `TELEGRAM_ORDERS_CHAT_ID` - чат для прежних заказов из каталога.
   - `LEMONZ_PROMO_CODES` - необязательный список прежних общих промокодов формата `КОД:ПРОЦЕНТ` через запятую. Новые промокоды удобнее создавать во вкладке администратора, без изменения переменных окружения. Для отключения старого кода из env админка создаёт в БД блокирующую запись.
7. Настройте вызов `GET /api/cron` с заголовком `Authorization: Bearer ВАШ_CRON_SECRET` каждые 5 минут (подходящий cron-сервис либо тариф Vercel, поддерживающий такую частоту). Он автоматически закрывает сезоны и лоты, отсчитывает сроки оплаты и отправляет уведомления.
8. Откройте Mini App под админом, внесите 3 героев LEMONZ, загрузите аукционные лоты и во вкладке «Промокоды» добавьте первые скидочные коды.

## Ограничения до реального запуска

- Стикеры Telegram пока не подключены. Работают фото и GIF.
- Персональные коды теперь автоматически проверяются в корзине. Поскольку денежная оплата пока вне приложения, окончательное погашение одноразового кода после оплаты отмечает администратор. Чтобы пользователи не могли оформлять произвольные цены, перед реальными продажами стоит перенести цены каталога из локального хранилища в серверную базу: сейчас API перепроверяет арифметику и действительность скидки, но базовые цены товаров всё ещё приходят от клиента.
- Списание денег не реализовано. Победитель оплачивает после аукциона отдельно по инструкции.
- Для первого баннера главной создан тематический арт `public/home-hero-dolls.png`, а из присланного скриншота добавлены точные визуальные фрагменты промокарточек и витрины. **Важное отличие:** Iso, Reyna, Gojo и прочие изображения с референса являются концептами витрины, а не добавленными в продажу товарами. Если их нет в каталоге, нажатие покажет сообщение о предстоящем появлении вместо создания фиктивного заказа. Для существующих товаров из каталога используются реальные цены. Из истории Git восстановлены доступные изображения **Clove**, **Chamber** и **Jinx** для каталога.
- Перед публикацией нужно выполнить SQL-миграцию и проверить Telegram-бота, уведомления, сезоны, ставки и оплату на тестовом сервере. В локальной проверке реальные ключи и база не использовались.

Для редактирования действующего сезона дополнительные таблицы не нужны: используются существующие поля `seasons.starts_at`, `seasons.ends_at` и каскадное удаление голосов и комментариев из схемы. Администратор может менять срок и список участников без запуска нового сезона. Если дата начала установлена в будущем, сервер отклоняет голоса и новые предложения до наступления этой даты.

Для управления общими промокодами необходима таблица `promo_codes` и атомарная серверная функция `manage_promo_code`, которые добавлены в основную схему и отдельную миграцию для существующих установок. Сервер проверяет право администратора по подписанным Telegram `initData`, клиент не имеет прямого доступа к редактированию БД. При переименовании существующего кода старое имя перестаёт работать. Коды персональных наград нельзя подменить общими.

## Конструктор парфюма: управление наборами

В админ-панели есть отдельная вкладка **«Наборы парфюма»**. Старый переключатель «Парфюм» перенесён сюда. Здесь можно скрыть или показать конструктор, добавить оформление коробки, изменить название и цвета, загрузить прямо с устройства фотографию лицевой панели и (необязательно) готового комплекта, а также удалить ненужное оформление. При выборе комплекта в конструкторе покупатель увидит эти фотографии; выбранное оформление и ароматы попадут в корзину.

**Для общего управления всеми пользователями** выполни в Supabase SQL Editor миграцию `supabase/migrations/20261101_perfume_config.sql` (в том числе на новой базе после основного `schema.sql`). Настрой переменные `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN` на Vercel. В Supabase Storage необходим публичный bucket `lemonz-media` с разрешёнными PNG/JPEG/WEBP/GIF. Фотографии из админки загружаются через защищённое Telegram-подписью API и сохраняются в Storage; интерфейс хранит только публичные URL. Редактирование набора требует прав администратора и сохраняется в `perfume_config` с проверкой версии.

Без подключённого сервера приложение использует **локальный пробный режим**, изменения сохраняются только на устройстве, не попадают к другим покупателям и не загружаются в Supabase. Это обозначено в админке. Локальные изображения оптимизируются браузером и сохраняются как небольшие WebP; при больших объёмах памяти браузера может не хватить. При наличии сервера загруженная фотография сохраняется в Supabase. Появление изменений на других устройствах происходит после обновления страницы.



## Управление ароматами в конструкторе

В админ-панели открой **Наборы парфюма**. Оформления коробок выбираются в компактном выпадающем списке. Ниже находится редактор ароматов: поиск, создание, редактирование, удаление, смена категории, аудитории, нот, цены за 2 мл и изображения. Фото загружается с устройства через `/api/admin-perfume-image` после проверки подписанных данных Telegram и прав администратора. Для хранения используется существующий публичный Supabase bucket `lemonz-media`.

После прежней миграции `supabase/migrations/20261101_perfume_config.sql` выполни **`supabase/migrations/20261101_perfume_aromas.sql`**. Она добавляет редактируемый список ароматов в `perfume_config`, сохраняя настройки оформления коробок. До первого редактирования остаются доступными 50 стартовых ароматов.

Для общего редактирования всем покупателям нужен сервер Vercel с секретами `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN`. Если сервер не настроен, действует пробный локальный режим - фотографии и изменения не синхронизируются между пользователями. Заказы с парфюмом сверяются на сервере с текущими ценами и составом; если аромат или цена изменились после добавления в корзину, покупателю потребуется собрать набор заново.


## Если в админке написано «Не подключён сервер промокодов»

Это сообщение означает, что опубликованная версия получила ответ `503 SERVER_NOT_CONFIGURED` от `/api/admin-promos`, а не то, что пользователь не является администратором. Само наличие сайта на Vercel не означает подключённую базу.

1. Создай/открой проект Supabase. На новой базе выполни `supabase/schema.sql`; на уже созданной базе проверь схему и выполни `supabase/migrations/20261024_promo_management.sql` в SQL Editor.
2. В Vercel → Project → Settings → Environment Variables добавь **серверные** `SUPABASE_URL` (Project URL), `SUPABASE_SERVICE_ROLE_KEY` (service role, секрет!) и `TELEGRAM_BOT_TOKEN` (токен бота через BotFather). Вноси значения только в Vercel, **никогда** в GitHub, в `VITE_` переменные или в чат.
3. Примени переменные к Production и запусти новый deployment в Vercel.
4. Открой Mini App именно через Telegram с аккаунта администратора, перейди в «Админ» → «Промокоды» и нажми «Повторить проверку».

Если ошибка осталась, сообщение теперь уточняет, относится ли она к авторизации (401), правам (403), миграции Supabase или адресу серверного API.

**Пробный редактор** в разделе доступен даже при неисправном сервере, но его коды хранятся только в браузере и **не действуют для покупателей**. При работе с настоящими заказами требуется серверный режим.



## Проверка интеграций, деплоя и безопасных заказов

В репозитории добавлен GitHub Actions `.github/workflows/ci.yml`: при каждом push в `main` автоматически выполняются `npm ci`, `npm run lint`, `npm test`, `npm run build`. Проверяй результат в GitHub → Actions. Успешная сборка Vercel не проверяет секретные переменные или состояние Supabase автоматически.

**Оформление заказов:** `/api/create-order` требует подписанный `x-telegram-init-data`, перепроверяет Telegram ID покупателя и для наборов парфюма дополнительно сверяет цены с общей базой. Покупателю нужно открыть Mini App из Telegram, а не просто в обычном браузере. Без `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ORDERS_CHAT_ID` заказы не отправляются. Цены обычных фигурок по-прежнему приходят из локального каталога; для полноценной защиты от изменения стоимости на клиенте необходим серверный каталог.

**Конструктор:** если API настроек недоступен на опубликованном сайте, админка блокирует редактирование и показывает причину. Пробный локальный режим остаётся только для разработческой сборки `npm run dev`. Это предотвращает ошибочное впечатление, что добавленный на телефоне аромат уже доступен всем.

**Обязательные сервисы до запуска:** проверь Vercel → Project → Settings → Environment Variables, SQL миграции `supabase/migrations/*`, bucket `lemonz-media`, Telegram-подпись и настройки планировщика (cron). Никогда не добавляй `SUPABASE_SERVICE_ROLE_KEY` или токен бота в GitHub и клиентские переменные `VITE_`.

## Серверные ключи и обслуживание Supabase

В `SUPABASE_SERVICE_ROLE_KEY` можно сохранить современный секретный ключ `sb_secret_...` (предпочтительно) или старый JWT `service_role`. Имя переменной сохранено для совместимости. Современный ключ отправляется только в заголовке `apikey`; старый JWT также передаётся в `Authorization`. Один способ авторизации используется для базы и загрузки изображений. Ключ предназначен только для сервера.

Миграция `20261101094311_media_storage_and_function_hardening.sql` создаёт `lemonz-media`, если bucket отсутствует, и сохраняет настройки существующего bucket. Также она фиксирует `search_path` функций: генератор кодов победителей должен видеть `pgcrypto` в схеме `extensions`. Публичное чтение изображений не открывает прямую загрузку файлов клиентам.

Миграция `20261101094341_maintenance_scheduler.sql` настраивает Supabase Cron для вызова production `/api/cron` раз в пять минут. Случайный секрет создаётся внутри Vault под именем `lemonz_cron_secret`. Его нужно безопасно перенести в секретную переменную Vercel `CRON_SECRET` и выполнить новый production-деплой. В SQL-файле и задании планировщика хранится только имя секрета. Перед применением к другому приложению проверь URL в миграции.

Первичная схема создаёт пустой сезон и настройки парфюма. Настоящих кандидатов голосования, промокоды и аукционные лоты добавляет администратор через Mini App. Демонстрационные записи не переносятся в общую базу автоматически.
